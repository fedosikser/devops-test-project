```markdown
# 🎯 Задание: Докеризация и развертывание приложения

## 📖 Легенда
Вы получили проект простого веб-приложения на Flask с подключением к PostgreSQL. Ваша задача — подготовить инфраструктуру для запуска этого приложения в контейнерах.

## ✅ Требования

### 1. Linux (Виртуальная машина)
- [ ] Поднять VM (Ubuntu или Debian)
- [ ] Создать пользователя `deployer` с правами `sudo`
- [ ] Настроить SSH-доступ по ключу (запретить вход по паролю)
- [ ] Настроить файрвол: открыть порты 22 (SSH) и 80 (HTTP)

### 2. Git
- [ ] Создать репозиторий и загрузитьв свой GitHub-аккаунт
- [ ] Создать ветку `feature/dockerize`
- [ ] Все изменения делать только в этой ветке
- [ ] Сделать осмысленные коммиты (использовать Conventional Commits)
- [ ] Открыть Pull Request в `main` ветку

### 3. Docker
- [ ] Написать `Dockerfile` для приложения:
  - Использовать легковесный базовый образ (Python slim или alpine)
  - Оптимизировать слои (копировать `requirements.txt` отдельно от кода)
  - Использовать multi-stage build (опционально, но приветствуется)
  - Не запускать контейнер от root (создать непривилегированного пользователя)
  
- [ ] Написать `docker-compose.yml`:
  - Сервис `web` (ваше Flask-приложение)
  - Сервис `db` (PostgreSQL 13+)
  - Настроить внутреннюю сеть между сервисами
  - Подключить volume для сохранения данных БД
  - Передать переменные окружения для подключения к БД
  - Пробросить порт 80 хост-машины на порт 5000 контейнера

### 4. Развертывание
- [ ] Склонировать свой форк на VM
- [ ] Переключиться на ветку `feature/dockerize`
- [ ] Запустить приложение через `docker compose up -d`
- [ ] Убедиться, что приложение доступно по HTTP на порту 80

## 📝 Критерии оценки

### Предпологаемая структура проекта
    devops-test-project/
    ├── app/
    │   ├── app.py
    │   └── requirements.txt
    ├── .dockerignore          ← часто забывают
    ├── .env                   ← НЕ в Git!
    ├── .env.example           ← шаблон для Git
    ├── .gitignore
    ├── docker-compose.yml
    ├── Dockerfile
    └── README.md

### Обязательные (без них задание не принимается):
- Приложение доступно по HTTP
- БД подключена и работает (проверка через `/health`)
- Данные в БД сохраняются после перезапуска контейнеров

### Дополнительные баллы:
- ✅ Multi-stage build в Dockerfile (-50% к размеру образа)
- ✅ Непривилегированный пользователь в контейнере
- ✅ Использование `.env` файла для переменных окружения
- ✅ Добавлен `healthcheck` в docker-compose.yml
- ✅ Красивая история коммитов (Conventional Commits)
- ✅ Подробное описание в Pull Request

## 📤 Что сдать

2. Скриншоты или asciinema-запись:
   - `docker ps` (запущенные контейнеры)
   - `curl http://localhost/health` (результат health check)
   - `docker compose down` → `docker compose up -d` → повторный curl (проверка сохранения данных)
   - `docker images` (размер образа)

## 💡 Подсказки

- Используйте `docker compose logs -f` для отладки
- Проверьте, что переменные окружения правильно передаются в контейнер
- Не забудьте, что внутри контейнера `localhost` — это сам контейнер, а не хост!
- Для PostgreSQL используйте переменные `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`

Удачи! 🚀
```
